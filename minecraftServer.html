Self-Hosting a Minecraft Server (and Accidentally Learning Infrastructure)

Summary

I want to share a personal project I’ve worked on in my free time that combines a long-time interest (games) with a newer one (infrastructure).

This wasn’t planned from the start. It sort of evolved as I learned more, broke things, and got advice from people who knew better.

I love playing videogames, specifically, I love hosting private Minecraft worlds for me and my friends. For years, I used managed game-hosting services, since they didn’t require me to keep my own machine running 24/7 and generally offered decent performance.

But being the frugal individual that I am, I eventually asked myself: “How can I save money doing this?”

Most game-hosting providers charge monthly based on RAM (roughly £10/month for ~8 GB). I found that a small server with 8 GB of RAM cost around £110 (pre-AInflation). At that point, I’d technically break even in under a year.

Of course, electricity isn’t free, and estimating the cost of running a server 24/7 with variable load is difficult. Still, after telling myself “It’s for learning!”, I caved and bought a home server.

It came with Windows Server preinstalled, which I removed immediately and replaced with Ubuntu Server.

First Working Setup

To get things running quickly, I used a service called AMP to manage and spin up the Minecraft server. It handled most of the heavy lifting and gave me a web UI to monitor the server.

Since my home connection doesn’t have a public static IP, I also used a tunneling service playit.gg so my friends could connect without me touching router settings.

And… it worked.

No major issues, aside from occasional lag spikes (likely due to the free tunneling service). But I wasn’t satisfied.

Why I Rebuilt It

A few things bothered me:

  • I didn’t love relying on a “free” tunneling service long-term
  • AMP abstracted away almost everything, so I wasn’t actually learning much
  • I was told (correctly) that I should be using Docker

So I decided to:

  • Get rid of AMP
  • Remove the tunneling service
  • Dockerise the Minecraft server

Dockerising the Server

Removing AMP wasn’t especially clean; it involved manually stopping and disabling services via 

systemctl
If there’s an easier way, I’m not aware of it.

After that, I installed Docker and Docker Compose, configured a compose.yaml, and started the server with: 

docker compose up -d

This gave me much more control, better isolation, and a setup I could actually reason about.

Networking and DNS

I already owned a domain hosted with Mythic Beasts, which made things easier. I created a subdomain and pointed it at my public IP.

The problem, of course, is that I don’t have a static IP, so it changes occasionally.

Thankfully, Mythic Beasts provides an API for dynamically updating DNS records. I used a small Bash script that:

  • Checks the current public IP
  • Compares it to the last known value
  • Updates the DNS record via the API if it changed
#!/usr/bin/env bash
            HOSTNAME=domain
            USERNAME=mythic beasts
            PASSWORD=mythic beasts pwd
            IPPROVIDER=https://ipv4.wtfismyip.com/text

            IP=`curl -sS $IPPROVIDER` # query Current IP

            function valid_ip()
            {
                local  ip=$IP
                local  stat=1

                if [[ $ip =~ ^[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}$ ]]; then
                    OIFS=$IFS
                    IFS='.'
                    ip=($ip)
                    IFS=$OIFS
                    [[ ${ip[0]} -le 255 && ${ip[1]} -le 255 \
                        && ${ip[2]} -le 255 && ${ip[3]} -le 255 ]]
                    stat=$?
                fi
                return $stat
            }

            DIR="$( cd "$( dirname "${BASH_SOURCE[0]}" )" && pwd )"
            LOGFILE="$DIR/update-ip.log"
            IPFILE="$DIR/update-ip.ip"
            DATE=`date`
            if ! valid_ip $IP; then
                echo "Invalid IP address: $IP" >> "$LOGFILE"
                exit 1
            fi

            # Check if the IP file exists
            if [ ! -f "$IPFILE" ]
                then
              touch "$IPFILE"
            fi

            if grep -Fx "$IP" "$IPFILE"; then
                # code if found
                echo "$DATE IP is still $IP. Exiting" >> "$LOGFILE"
                exit 0
            else
                echo "$DATE IP has changed to $IP" >> "$LOGFILE"
                echo "$IP" > "$IPFILE"


            curl -X POST https://ipv4.api.mythic-beasts.com/dns/v2/dynamic/$HOSTNAME -d username=$USERNAME -d password=$PASSWORD
            echo "$DATE updated IP address to $IP" >> "$LOGFILE"

            fi

            exit 0

This script runs every 10 minutes via cron.

Making It Reachable

Even with DNS set up, the server still wasn’t accessible, as home routers block unsolicited inbound traffic by default.

To fix that, I:

  • Assigned a static private IP to the server
  • Set up port forwarding for Minecraft
  • Set up port forwarding for SSH (for remote access)

At that point, my friends could connect using a stable domain name, without tunneling services.

Final Notes on Security

Access to the Minecraft server is restricted using a whitelist of Microsoft accounts, and SSH access is locked down.

That said, it’s still theoretically vulnerable to DoS attacks. Because of that, I keep the domain and subdomain private.

What I Got Out of This

This project gave me hands-on experience with:

  • Linux server administration
  • Docker and Docker Compose
  • DNS and dynamic IP handling
  • Networking
  • Automation
